# Arks Scanner mobile app (Flutter)

Android first; iOS builds from the same code later. Design: [docs/superpowers/specs/2026-10-29-flutter-mobile-app-design.md](../../docs/superpowers/specs/2026-10-29-flutter-mobile-app-design.md).

The app uses the same API, Firebase project and server processing as the website. All image processing (crop, scan looks, OCR, text edits, PDF) stays on the server, so results match the web exactly.

## What works now (MVP milestones 1–4)

- Sign-in required (Google, email/password, password reset); one-time privacy consent; settings with download my data and delete account.
- My documents: phone-saved documents, plus cloud documents (Pro) or documents still being edited (Free).
- **Scan** with the phone's document scanner (Google ML Kit: live edges, auto-capture, several pages), or **import** photos/PDFs.
- Pages appear as the server finishes them. Reorder (drag), remove, add more pages.
- Page view: pinch-zoom, scan-look strip (Magic scan, Original, Document, Bright, No shadow, Grayscale, Black & white), rotate, auto-detect edges, and full-screen corner adjustment with a magnifier.
- Share PDF, print, and **Save to phone**:
  - Free: saves the PDF and page images in the app's private storage, then deletes the server copy (`DELETE /api/documents/{id}?savedToDevice=true`, purged on the next purge run).
  - Pro: saves a copy and keeps the cloud document.
- Phone-only documents: swipe through pages, share, print, rename, delete, **Edit again** (re-uploads the pages as a new document).
- Sign-out warns and then removes phone-only documents.
- **Edit tools** (page screen → Eraser · Text · Sign · Tick):
  - **Eraser:** paint over holes, staples or specks (3 brush sizes) or **Find holes**, then Preview with a before/after toggle, then Apply.
  - **Text:** recognise text (OCR) on the page. Then:
    - **Replace:** tap words; the server proposes the font, size and colour.
    - **Add text:** tap where it should go.
    - Editing happens in a bottom sheet with a live preview strip. The strip thickens weights above the real face exactly like the server.
    - Options: font (42 families in 4 groups), weight, size, colour, alignment, spacing and strikethrough.
    - Preview shows the exact server render; Apply saves the edit. Undo and redo are in the top bar.
  - **Sign:** draw with a finger, or use a photo (the server removes the background); then place, move, resize and delete.
  - **Tick / Cross:** tap to place; tap a mark to move, resize, recolour or delete it.
  - Signatures and marks are drawn into the PDF on export, as on the web.
- **Search** (document screen 🔍): searches recognised text across all pages on the phone, ignoring case and accents like the web. It can also recognise pages that haven't been done yet.
- **Languages:** English, Bahasa Melayu, 中文（简体）, العربية (right-to-left). The app follows the phone's language, or the choice in Settings → Language.

Not built yet: push notifications, in-app purchase, rewarded ads, app lock, offline mode.

### Translations

Strings live in `lib/l10n/app_*.arb`.
- English (`app_en.arb`) is the source.
- Malay, Chinese and Arabic are generated by `tool/gen_translations.py`, which refuses to write if a key or placeholder is missing.
- `test/edit_tools_test.dart` checks that all four files stay in sync.
- The translations are machine-quality. Send them for native-speaker review alongside the web's `docs/translation-review` files, then edit `tool/gen_translations.py` and rerun it.

The text editor's live preview loads fonts on demand, as the website does:
- Latin and handwriting fonts come from the website's public `/assets/fonts` (set `WEB_BASE_URL`).
- World-script fonts come from the API.
- If a font can't load, only the live guide falls back. **Preview** is always the exact server render.

## One-time Firebase setup (needs the Firebase account owner)

1. Firebase Console → project **superscanner-dev** → Project settings → **Add app → Android**.
   - Package name: `com.arksoft.arksscanner`.
   - Add the **SHA-1** and **SHA-256** of the debug signing key. Get them with `cd android; .\gradlew signingReport`. Google sign-in and Play Integrity need them.
   - You don't need `google-services.json`; the app reads its settings from build flags instead.
2. Copy the Android **App ID** (looks like `1:122650027029:android:…`).
3. **App Check → Apps →** the Android app → register **Play Integrity**. For development, run a debug build once; it logs an App Check **debug token**. Add that token under **Manage debug tokens**.
4. Add the Android App ID to the API's allowed apps: `Firebase__AllowedAppIds__1=<Android App ID>` (local: `local-env.ps1`; Railway: API service variables).
5. Authentication → Sign-in method: Google and Email/Password must be enabled (they already are for the web).

## Run on a phone

1. Enable **Developer options → USB debugging** on the Android phone and connect it by USB. Run `flutter devices` to check that it's detected.
2. The phone must reach the API (and the web app, for editor fonts). On the same Wi-Fi, use the PC's LAN IP. The local servers listen on localhost only by default, so either:
   - start the API with `--urls http://0.0.0.0:5093`, or
   - forward the ports over USB with `adb reverse tcp:5093 tcp:5093` and `adb reverse tcp:4200 tcp:4200`, then use the localhost URLs below.

```powershell
cd apps/mobile
flutter run --dart-define=FIREBASE_ANDROID_APP_ID=<Android App ID> --dart-define=API_BASE_URL=http://localhost:5093/api --dart-define=WEB_BASE_URL=http://localhost:4200
```

Build an installable APK:

```powershell
flutter build apk --debug --dart-define=FIREBASE_ANDROID_APP_ID=<Android App ID> --dart-define=API_BASE_URL=<API URL>/api
```

The APK is written to `build/app/outputs/flutter-apk/app-debug.apk`.

Notes:
- The ML Kit scanner needs **Google Play services**. It works on normal Android phones, but not on most emulators or Huawei phones without Google services. Import from files still works there.
- Debug builds allow plain `http://` (for the local API). Release builds require `https://`.

## iPhone test build (from Windows, no Mac)

iOS apps can only be built on macOS, so [`codemagic.yaml`](../../codemagic.yaml) builds an unsigned `.ipa` on Codemagic's cloud Mac. Sideloadly then signs it with a free Apple ID and installs it.

1. In Firebase, **Add app → iOS** with bundle ID `com.arksoft.arksscanner`. Add its App ID to the API as `Firebase__AllowedAppIds__2`.
2. In Info.plist, add the URL scheme Google sign-in needs: the iOS App ID with `:` replaced by `-` and prefixed with `app-`.
3. In App Check, add a debug token (any UUID) for the iOS app.
4. In Codemagic, create the environment variable group `ios_test` (see the comments in `codemagic.yaml`). Then run the **iOS test build** workflow and download `ArksScanner-unsigned.ipa`.
5. In Sideloadly, sign in with your Apple ID and install the `.ipa` to the iPhone over USB.
6. On the iPhone:
   - **Settings → General → VPN & Device Management →** your Apple ID **→ Trust**.
   - **Settings → Privacy & Security → Developer Mode → On** (requires a restart).

Notes:
- Free Apple ID installs expire after **7 days**; reinstall with Sideloadly.
- The API must be reachable over **https** from the phone, so localhost won't work.
- Passing `APP_CHECK_DEBUG_TOKEN` makes a release build use the App Check debug provider. Store builds must not set it; they use App Attest.

## Tests

```powershell
flutter analyze
flutter test
```

The tests run against a fake HTTP server, so no phone or Firebase is needed:
- `test/app_logic_test.dart` covers the API client headers and errors, the upload flow, the document models, and saving to the phone.
- `test/edit_tools_test.dart` covers OCR word flattening, search, eraser revisions and strokes, mark and text-edit requests, and translation parity.
